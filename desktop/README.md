# Orbyn Planner desktop

A thin Tauri 2 shell around the web app in `../web`: one window, the standard menus, and the window's size and position remembered. It has two commands for the page to call (`open_link`, and `save_export`, which saves an export through the system's save dialog) and no network code; the page talks to the engine itself.

## Needs

Node 22, the stable Rust toolchain (1.90 or newer) and the [Tauri system requirements](https://tauri.app/start/prerequisites/) for your platform.

## Run

```bash
cd web && npm ci && cd ../desktop && npm ci
npm run dev      # starts the web dev server and opens the window on it
npm run build    # builds the web app, then the app and its installer
```

The engine address is set in `config.json` (`engineUrl`). `scripts/tauri.mjs` writes it into the content security policy, so the window may fetch from that one origin and nothing else.

## Icons

`app-icon.svg` is the source. After changing it, run `npm run icons` and commit `src-tauri/icons/`.

## Checks

```bash
npm test                          # the config and CSP scripts
cd src-tauri && cargo test        # the navigation allowlist
cd src-tauri && cargo clippy
cd src-tauri && cargo audit     # dependency advisories
```

**Builds are unsigned and not notarised yet.** macOS will warn about an unidentified developer and Windows SmartScreen about an unknown publisher; installers are for testing only.

Production builds need an `https://` engine URL (`ORBYN_ENGINE_URL`); plain `http://` is accepted only for localhost and 127.0.0.1 in `npm run dev`.

The window's content security policy is generated by `scripts/tauri.mjs` from that URL, so a release build allows its own origin, the one engine origin and nothing else. A release build whose policy would allow localhost, 127.0.0.1 or ::1 (for example `https://localhost:8443`) fails before anything is built; only `npm run dev` adds localhost and the dev server. The `csp` in the checked-in `tauri.conf.json` is the closed policy with no engine at all, so a build that skips the script can reach no engine instead of reaching a local one.

Links in notes open in the system browser through the shell's single `open_link` command, which accepts http(s) addresses only. A primary click and a middle click (`auxclick`) both do; the window never navigates to a link.
